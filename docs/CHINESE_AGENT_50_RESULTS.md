**真正核心错误是第48题**：把Feb 18, 2021文章时间误当成上映日，正确应为2月12日。第09题把1月17日和1月28日并列而不消解矛盾，算部分正确；第22、34题只覆盖部分必答信息。第30题数字有原文依据但与参考统计对象不同，保守标uncertain；第43题原文明示从2.3%修订为2.2%，接受修订值。

本轮最明显的瓶颈是**工具决策与证据管理**，其次是实体/年份限定下的检索排名，以及日期、范围和冲突证据的解释。具体证据是：32题英特尔631亿美元已检索到却不再对最终模型可见；45/47题根本没检索；22/34题缺项仍停止；48题把发布时间当事件时间。这只是从本轮案例归因，不是消融实验，不能断言换单一模块必然提升多少。

可先尝试Prompt改进（本轮未实施）：要求按必答项自检；缺项先补查；区分发布时间、事件时间、集团/品牌/分项口径；遇冲突说明取舍；简单题只回答所问；不得编造Source ID；避免仅改空格或错误翻译实体。Prompt不能保证以上约束每次都被执行。

必须考虑代码层保障（本轮未实施）：按子问题保留证据的上下文压缩；引用校验失败后可恢复到有预算的检索步骤并保留已支持的部分回答；证据语义对齐和引用选择检查；工具参数缺字段的可诊断反馈；对模型失败保留脱敏异常类型与Usage可用性；将claims JSON与用户正文可靠分离。不能用放松权限或引用验证来换取分数。

下一轮最值得做的三件事：

1. **保护跨工具、跨子问题证据。** 修复32题这种已命中却因压缩丢失的链路，并在同样冻结评测上验证，不能只提高检索Top-K。
2. **建立答案必答项与补查决策约束。** 覆盖零工具回答、已知缺项停止、重复无效读取；保持安全拒答，但允许有依据的部分答案。
3. **对齐每个事实与引用语义。** 优先处理44/48/50的错引、发布日期误用和反事实混引，同时减少简单答案的扩写、工具Schema和返回元数据开销。

没有实施上述优化，也没有执行新一轮测评。此次只是评测、审查和交付。
