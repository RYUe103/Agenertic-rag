# 平台改造进度

依据用户提供的《Agentic RAG 前端升级为 AI 知识与工具平台》提示词及后续多知识库要求维护。此文件记录代码实际状态，不以页面入口代替后端能力。

## 已实现或部分实现

- 总览按账号可访问的已启用知识库汇总文档、处理状态、工具、未撤销接入和 Agent 执行，并列出最近文档、任务、执行和工具调用；组织成员的执行记录按本人及当前知识库权限过滤。
- 文档管理、上传、资料解析和 Dify 索引：使用持久化队列，单个或批量重新解析可在任务中心跟踪；入库、重新解析和删除任务支持取消未开始的项目，并等待运行中的项目结束；文档详情可查看解析目录和 Dify 实际分段。
- 新上传文档保存文件大小、上传账号和可读取的 PDF 页数，列表及详情显示这些字段；历史记录和非 PDF 页数未采集时显示未知，不推断上传人或页数。
- 统一解析入口：配置 MinerU 后 PDF、DOC、DOCX 和 TXT 均先提交同一解析入口，保留真实文件名和 MIME 类型；支持本地同步 HTTP 服务，也支持官方云端 v4 API（预签名上传、异步轮询、Markdown/ZIP 结果下载）。服务失败时按 `MINERU_FALLBACK_ON_ERROR` 决定回退本地解析或失败，解析记录标明请求引擎和回退原因。当前环境未配置 MinerU URL，因此默认仍使用本地解析。
- 知识库编辑页提供解析器选择，并明确 MinerU 选项对所有支持格式生效；管理员可为单个知识库选择 MinerU、本地或 PDF 专用视觉解析。
- 文档索引重建：文档列表支持单个或批量创建独立后台任务，使用已确认 Markdown 重新提交 Dify，任务中心可筛选、暂停、取消和重试失败项；索引处理中恢复服务会继续查询状态。展示的是 Dify 返回的整体索引状态，不推断独立 BM25 或向量阶段。
- 批量删除：文档列表创建持久化删除任务，在任务中心显示并支持取消未开始项；同一知识库只允许一个活动删除任务，创建时检查已有入库队列。实际删除使用跨进程知识库独占锁，与入库、解析、改写及索引操作互斥，旧直接上传也受保护。删除与入库队列仍使用独立数据库，任务创建的检查并非跨库原子事务；并发提交的任务可能先后执行，仍需统一调度。
- 上传页列出文件大小并提示同名文件，上传失败后可在当前页面继续原任务；新任务会保存文件大小，刷新后可从任务中心重新选择未上传文件继续。恢复时校验文件名和大小，不可区分的同名同大小文件会被拒绝；旧任务没有大小信息，无法这样恢复。上传中的任务可取消，实际上传用户名传入文件平台；文件名和大小不能证明内容完全相同。
- 文档版本：解析发布、重新解析及人工确认改写会保存独立 Markdown 快照，文档详情可查看历史内容、内容哈希、解析器和创建快照时的索引状态。旧版状态记录没有保留正文，不冒充历史快照；新快照从本次功能启用后开始记录。
- 文档版本快照同时记录创建时的分块模式、最大 Token 和 Embedding 模型标识；未配置或旧快照缺失时显示未采集，不从 Dify 推断模型。
- 检索测试：知识库列表可打开检索抽屉，调用 Dify 的全文、向量或混合检索，支持 Top-K 和 Dify 元数据过滤 JSON，显示分数、分段、真实耗时和未匹配本地文档数量；页码及章节未采集时明确标注。
- 任务事件：持久化文件接收、任务排队、处理开始、重试和结束等实际事件。原始文件保存、文档解析、基础元数据提取、Dify 文档提交、索引状态查询及文件平台上传会记录开始、结束、失败和耗时，任务中心可分页查看；事件不会回填到旧任务。
- 知识库：用户按名称、Dify Dataset ID 和密钥创建；平台生成内部 ID，选择知识库后复用默认 Agent。后台入库任务保存稳定的知识库运行标识。
- 知识库列表按当前账号权限显示本平台记录的文档数和已索引文档数，未采集完整分段总数时明确显示未采集；这些数量不包含仅存在于 Dify 的文档。
- 知识库元数据：知识库列表可维护自定义字段标识、名称、类型和提取说明，以及 AI 提取开关和提示词；保存后更新实际解析运行时，重复字段标识由后端拒绝。已有文档需要重新提取元数据才会应用新配置。
- 访问边界：知识库按所有者授权；旧版默认知识库接口检查归属；共享 Agent 配置由管理员管理。
- 工具中心：展示当前 Agent 已授权且实际存在的知识/文档工具，包括 Dify 检索、全文、页、章节、表格、状态和相邻分段读取，以及上传文档、删除文档、重新解析和重建索引工具。写入工具要求文档写权限、人工审批和现有持久化任务/生命周期实现；上传通过 Base64 内容创建异步入库任务并受 25 MB 单文件限制。提供参数与输出 Schema、真实测试调用、外部和内部 Agent 调用统计及最近调用记录；既有 Agent 和外部接入需分别授权新增工具。
- 外部接入：为每个客户端创建独立密钥，按知识库和工具授权，支持修改授权范围、轮换、撤销和调用记录；仅保存密钥哈希。独立密钥适用于 REST、可选 MCP Streamable HTTP 和非流式 OpenAI-compatible 接口。OpenAI 兼容接口使用 `@kb:<知识库 ID>` 模型标识，Agent 调用受工具授权约束且不启用代码执行；历史全局 API Key 仍可使用，其权限不受独立接入配置限制。
- 文件平台：管理员可为知识库选择继承全局、本地或已配置的平台。普通用户无法修改平台连接。
- Agent 执行记录：问答和检索记录状态、耗时、工具调用数与轨迹摘要；支持按知识库、状态和类型筛选及分页，按账号和知识库检查访问权限，不保存问答正文和检索参数。
- 可选 Supervisor：管理员配置 Knowledge、Research、Data Analysis、Coding 成员；支持按顺序执行或由模型选择成员，并可基于证据生成综合回答。后端要求 Supervisor 成员绑定同一知识库并共享至少一个授权工具；成员执行 LangGraph，限制工具与调用预算并保留执行轨迹；路由或综合校验不可用时回退。
- 审计日志：管理员可分页筛选登录、部分文档及配置操作、外部工具调用等真实事件；不记录请求正文或密钥。
- Sandbox 基础能力：默认关闭，管理员可配置普通用户是否允许执行、Python、Shell、执行时间、CPU、内存和临时空间；使用 Docker 非特权容器、只读根文件系统和禁用网络，执行记录按账号隔离。服务重启时会依据持久化容器名检测并清理遗留容器，将记录标为已恢复失败或结果未知。需要本机 Docker 和 `python:3.11-slim` 镜像。
- 运行监控：采集真实 API 调用次数、状态和耗时、任务队列状态、Agent 执行汇总、工具调用失败数；Sandbox 容器运行期间采集 CPU、内存和进程峰值，Docker 不提供数据时明确显示未采集。
- 用户与权限：持久化角色、权限和用户绑定；管理员可配置角色并为 LDAP 用户绑定角色，关键工具调用和 Sandbox 入口由后端权限检查，未登录用户不能依赖前端隐藏绕过。
- 组织与租户管理：管理员可创建组织、维护唯一租户标识、绑定和移除成员；知识库可绑定租户，成员可访问所属租户知识库，成员移除后其外部接入也不能继续访问。数据持久化在独立 SQLite 存储，接口有管理员权限、冲突和不存在租户检查。
- LDAP 管理：管理员页面可读取、保存和测试 LDAP 连接配置；绑定密码仅保存本地受限文件并以配置状态返回，运行时登录器会使用更新后的配置。支持用户组查询、组到平台角色映射，以及每次 LDAP 登录时的角色同步。
- 工具治理：检索和文档工具可启用人工审批，测试及外部调用需由管理员批准与账号、知识库、工具和参数绑定的申请；批准 15 分钟后过期且仅可使用一次，管理员可从工具中心清理过期记录。内部 Agent 遇到需要审批的工具时记录等待状态，批准后可从执行记录重新运行并消费审批；恢复时重新规划，若工具参数变化会再次申请审批。审批参数保存在本地数据库供管理员审核。
- 文档写权限：主要上传、解析、删除、元数据及任务操作增加后端检查；管理员和所有者允许写入，组织成员须有 `document.write`。知识库选择接口返回当前用户的实际文档写入能力，文档、上传和任务页面据此展示只读提示或操作入口；仍需逐一核对其他旧接口和页面。

## 未完成

- 改写等更多写入型工具仍未开放；工具中心现已提供真实的 Markdown 表格提取、CSV 导出和标准 XLSX 导出（导出文件由前端下载，不写入知识库存储）。Agent 审批恢复目前重新运行请求而非保存 LangGraph 检查点，完整调用审计仍未完成。
- 后续计划：将 Agent 审批恢复改为真正的 LangGraph checkpoint。需要为每次执行分配稳定的 `thread_id`，配置持久化 checkpointer，在审批处保存可恢复的 State，并处理服务重启、过期审批、并发恢复和写工具幂等；在完成这些约束前继续使用当前的重新执行逻辑，避免重复上传、删除或创建任务。
- 外部接入的真实第三方客户端兼容性验证和完整审计仍需完成；OpenAI 兼容接口目前不支持流式和 system 消息，离线安装包需要补齐 MCP 依赖。
- Supervisor 尚缺更多专业 Agent 与细粒度知识库授权；执行记录仍缺少实时事件与完整任务追踪。
- Sandbox 可在管理员允许时读取所选知识库文档的解析文本副本，Python 可通过只读 Knowledge SDK 查询；每次最多 10 个文档、总计 2 MB。支持将 `/tmp/output` 中最多 20 个、总计 2 MB 的普通文件持久化，并按执行账号授权下载；网络和依赖安装目前始终禁用。
- Agent 自动代码执行：Agent LangGraph 在当前请求拥有 Sandbox 权限且管理员允许 Python 时注入请求隔离的受控 `execute_python` 回调，结果进入执行过程轨迹；不满足策略或权限时不会暴露执行能力。
- 完整文档写权限覆盖和前端权限提示，以及完整身份联合登录端到端验收。
- 文档分段的页码和章节仅在 Dify 返回定位信息，或分段与解析正文唯一精确匹配时展示；MinerU 结构化内容列表含页码和标题时保留相应标记，无法确认的位置不推断。普遍适用的分段定位仍未完成；Dify 内部分块、BM25 与向量索引的独立阶段尚未采集，处理事件也尚不覆盖全部阶段和完整执行日志。
- CiteVQA 评测脚本已加入 `scripts/evaluate_citevqa.py`，可对真实标注和已入库 PDF 逐题调用 Agent，统计答案、文档召回、页码召回和耗时；已下载官方 validation 标注（1,897 题、711 份 PDF 引用），但当前机器未取得对应受限 PDF，因此尚未产生数据集评测分数。
- T²-RAGBench 已取得公开测试标注和一个真实 PDF 样本；该样本已通过 MinerU 云端解析（`parse_status=success`）。使用用户提供的真实 Dify Dataset 做了 3 题端到端检索验收：临时上传并索引 PDF 成功，全文检索和语义检索均返回目标文档，语义检索最高分约 `0.79–0.82`，三题均命中包含目标表格的分段；验收后已删除临时文档，未污染现有知识库。该结果只证明真实上传、索引和检索链路可用，不代表 T²-RAGBench 完整准确率，答案生成和全量评测仍需独立执行。
- 外部 AI 接入、监控与治理界面，以及上述能力的完整端到端测试。

上述缺口不能通过模拟数据或不具备隔离能力的本机命令执行冒充。旧接口继续保留，后续改造需考虑现有数据、排队任务和外部调用兼容。
